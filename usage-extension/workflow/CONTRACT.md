# Workflow evidence v1

This is deterministic accounting and protocol observation, not a waste detector or model advice. The shared contract is `types.ts`. `/usage` must never generate a model response for this feature.

## Component boundaries

- `extract.ts`: `extractWorkflowRecord(entry: unknown, line: number): WorkflowRecord | null`. Pure normalization of one parsed JSONL object. Optional measurements are unknown, not zero. No I/O, aggregation, raw transcript retention, model calls or application fixes. `opaqueWorkflowRecord(line: number): WorkflowRecord` is an optional helper.
- `analyze.ts`: `buildWorkflowSnapshot(inputs: readonly WorkflowInput[]): WorkflowSnapshot` and `workflowInsights(snapshot: WorkflowSnapshot, startDay?: string, endDay?: string): WorkflowInsight[]`. Pure aggregation and fixed neutral prose. Inputs arrive in canonical usage source order. No parser, index lifecycle or UI edits.
- Index adapter: add optional `workflow` capture to parsed files/chunks; stream normalization in the existing parse, preserve physical line numbers and append equivalence, invalidate old schema records safely, and carry the snapshot into `UsageData` and optional native `rollup.workflow`. No separate full-file crawl. Persist hashes/scalars only, not transcript bodies, tool arguments, source paths or secret excerpts. Cap retained workflow records at 30,000 per file and surface omitted coverage. Normalizing one large record must not undo the accounting parser's allocation-safe large-tool-result path; conservatively mark it opaque.
- HUD: decode optional `rollup.workflow` and show the same nine lenses for the selected local-day period. Old/absent/unsupported workflow data remains unavailable, not healthy. Bad optional data must not break valid old accounting. Consumer mapping is by named metrics, not position.

## Measurement definitions and controls

1. **Wakes/errors:** exact visible-content wake hashes from actual user/custom notifications with a literal `pr-latch:`, `pro-latch:` or `dot-latch:` marker. Count copies after the first occurrence separately from groups. Assistant stopReason error is a provider-error observation; errors with explicit zero counters still do not prove surrounding work was free. Bursts are at least three consecutive captured assistant errors, with no nonerror assistant between them (unknown timestamp gaps cannot establish elapsed time).
2. **Duplicate delivery:** full captured notification delivery body and later tool-result visible text have equal byte counts AND exact hashes. Only supported protocol wrappers may be projected; do not trim whitespace to manufacture exact equality. File-only notices, different report versions and partial previews are controls. Equality does not imply an unnecessary read or avoidability. Bound candidate windows and source references.
3. **Handoff:** an explicitly aborted captured conversation with no captured terminal stop+visible-text final report is an observation as of this snapshot. Never flag merely active/error-only work or claim no external artifact exists. One conversation is not necessarily one independent resumed run. Attribute the observation to its captured abort day; remove stale missing-handoff observations after a later final report.
4. **Verification:** pair tool call/results by actual call ID. Test/check-looking outer shell commands, filtered pipelines, force-exit flags, receipt `isError` and explicit numeric exit codes are independent facts. `isError=false`, printed pass counts, a report claim or grep output do NOT establish full compiler success. A nonzero receipt is not automatically a defect; expected baseline RED and justified recovery are protected.
5. **Chronology:** declared edit/write paths and first test/check-looking call in captured record order. `nonTestNamedMutations` means only paths that are not syntactically test-named; it does not mean production semantics. `firstTestAfterMutation` measures ordering, never proves a TDD violation. Literal baseline source-read commands are observations, not RED/GREEN proof. Do not inspect heredoc/script/application bodies as executed outer commands. Missing history/parent links are unknown.
6. **Startup:** initial stored system and first scoped user sections before the first assistant request, in UTF-8 bytes, excluding tool declarations/thought/image/signature blocks. Scope is captured conversations; only explicit declared roles identify children. These bytes are not provider tokens, replay costs or dispensable instructions.
7. **Roles:** attribution to a structured agent-role/name or an unambiguous self-identity declaration in initial system/task preamble only; otherwise unknown. No role inference from task topic or arbitrary later prose. Deduplicate copied records in canonical order; resumed records are one captured history, not new run charges. Sum explicitly recorded valuations with coverage; never call them billing/savings/waste. Pi counters use normalized uncached input + cache reads + cache writes; reasoning is a subset of output.
8. **Compaction:** captured compaction between adjacent assistant requests gives before/after normalized prompt footprints when all three input counters are known on both requests. Sum matched before/after only. No latency, causal cache-expiry or semantic-summary correctness claims. Keep branch parent relationships where supplied; ambiguous adjacency must not be presented as verified.
9. **Telemetry:** all captured eligible assistant records, including zero-usage errors, with separate complete prompt/output buckets, cost and reasoning coverage. Missing fields are unknown; malformed/negative/nonfinite values are not counters. Opaque/capped/unsupported sources disclose incomplete scan coverage. Never silently relabel partial data complete.

Use local calendar dates consistent with the old usage aggregation. Facts without usable timestamps may contribute to explicit global scan coverage but must not be fabricated into the current day. Evidence is bounded (at most three references per kind per day, at most 256 total) and includes conversation identity and physical source lines, never raw excerpts. For at most nine cards per selected period, merge daily numeric metrics first and use independent denominators; lenses overlap and are not a partition of all cost. Valuation is not an invoice. No counterfactual savings or automatic repair proposals.

## Regression and publication boundaries

Tests use anonymized synthetic fixtures. Include positive cases, benign controls, unknown/zero telemetry, copied/resumed history, malformed/untrusted inputs, append/rewrite/delete, backward-compatible native payloads and size/reference bounds. Observe assertion-based RED before implementation, then GREEN. Run only focused component tests in isolated worktrees; parent performs authoritative integrated gates. No dependency installs/network, paid inference, model changes, historical command execution, Git resets/restores/checkouts/switches or publication from workers. Private appserver/latch source replay and FoundationModels calibration are parent-owned and kept out of PR artifacts.
